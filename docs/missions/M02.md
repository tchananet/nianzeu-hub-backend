## Interface P01

0002_profiles suit 0001_identity ; huit tables conformément à data.md/profiles.md.
talent_profiles : id, user_id unique FK users, display_name, headline, bio, city,
country_code, availability, experience_level, rate_amount/rate_currency/rate_unit,
created_at/updated_at. UUID/timestamps fournis par le service.
skills : id/name/normalized_name unique = lower(name), six UUID fixes du contrat.
profile_skills : PK(profile_id, skill_id), FK skill RESTRICT, profil CASCADE.
experiences/certifications : UUID, FK profil, champs/dates contractuels, position 0..19
unique par profil, created_at ; bornes chronologiques en DB, dates futures au service.
contact_settings : profile_id PK/FK, email/phone/whatsapp nullable, flags false par défaut.
Chaque flag true exige sa valeur ; création atomique de la ligne assurée par P01.
profile_views : PK(profile_id, day), count >=0 ; pas de compteur implicite par défaut.
profile_view_dedup : PK(profile_id, day, visitor_hash), expires_at et index expiration.
Tarif tout nul ou complet, montant positif entier <=99999999.99, devise XAF,
unité hour/day/project. Chaînes requises non vides sauf bio/description.
Enums exacts du contrat ; code pays deux lettres majuscules, appartenance ISO au service.
Toutes les FK parent CASCADE, aucune indexation des coordonnées privées.
Index FK enfants couverts par PK/unique préfixé profile_id ; recherche ajoutée par M03.

# Q02 — charge

## Périmètre livré

`tests/load/` : harnais de charge complet, 17 fichiers, aucune dépendance ajoutée —
`httpx` (déjà groupe dev) et la bibliothèque standard (`concurrent.futures`, `random`,
`statistics` via un percentile au rang le plus proche) uniquement.

| Fichier | Responsabilité |
|---|---|
| `config.py` | configuration par variables d'environnement, garde-fou de cible jetable |
| `corpus.py` | 500 comptes/profils déterministes, préfixe `q02-<run_id>-`, sources |
| `phases.py` | échauffement 5 min, montée 5 min, plateau 20 min, descente 2 min |
| `session.py` | un client httpx par utilisateur virtuel, login, CSRF, chronométrage |
| `journeys.py` | le mélange 50/25/10/10/5 de A01 |
| `seeding.py` | amorçage register → login → `PUT /profiles/me`, budget d'inscriptions |
| `attribution.py` | préflight d'attribution des quotas par source ; scénario de refus |
| `runner.py` | pool d'utilisateurs virtuels, bascule plateau/hors-plateau |
| `metrics.py` | p50/p95/p99, erreurs par statut, débit, taux de 429, relevé par minute |
| `thresholds.py` | les seuils A01, cités en en-tête du module |
| `report.py` | rendu JSON, avec les métriques hôte explicitement en `null` |
| `cleanup.py` | SQL de purge imprimé, jamais exécuté |
| `conftest.py` | déclaration locale du marqueur `load` |
| `test_load_run.py` | la campagne, verrouillée par marqueur + `Q02_LOAD_TEST=1` |
| `test_harness_offline.py` | 18 tests hors-ligne des parties pures |
| `test_report_offline.py` | 3 tests du rendu : verdict PASS, lacunes hôte, échec p95 |

`docs/qa/load.md` : verdict et seuils. `docs/qa/load-procedure.md` : mélange, quotas,
procédure (scindé pour respecter la limite de 100 lignes par fichier).

Rien d'autre n'est touché : `app/`, les autres suites, `docker-compose.yml`,
`Dockerfile`, `pyproject.toml` et `uv.lock` sont inchangés.

## Verdict : BLOQUÉ, aucune mesure

Le critère de sortie du plan exige une campagne sur VPS de test autorisé. Il n'y a sur
cette machine ni VPS, ni démon Docker, ni PostgreSQL. **Aucun p95, p99, débit, taux
d'erreur, CPU, RAM ni comptage de connexions n'a été mesuré.** Les seuils A01 sont codés
et cités, pas évalués. Détail et conséquences : [../qa/load.md](../qa/load.md).

## Contrôles exécutés

```
python -m ruff check .                  # code 0
python -m mypy app                      # code 0, 104 fichiers
python -m pytest -q                     # 486 réussis, 5 ignorés, 246 erreurs
python -m pytest -q --ignore=tests/load # 465 réussis, 2 ignorés, 246 erreurs
python -m pytest -q -m load             # 3 ignorés, 734 désélectionnés
```

Les 246 erreurs sont antérieures (`BLOQUÉ : *_TEST_DATABASE_URL requis`) et inchangées
par cette mission. `pytest -q` collecte les 3 tests de campagne et les ignore.

## Deux décisions à connaître pour la suite

**Le marqueur `load` est déclaré dans `tests/load/conftest.py`**, pas dans
`pyproject.toml`, qui n'appartient pas à Q02. Si une mission future reprend la propriété
de `pyproject.toml`, déplacer la ligne dans `[tool.pytest.ini_options] markers` et
supprimer le conftest est le nettoyage attendu.

**L'amorçage dépend du proxy de test.** 500 comptes à 5 inscriptions/heure/IP imposent
exactement 100 sources distinctes et donc un proxy autorisé dont uvicorn accepte les
en-têtes transmises (`FORWARDED_ALLOW_IPS`, GAP-02). Sans cela l'amorçage s'arrête à
5 comptes et la campagne ne mesure que le limiteur de débit. Le préflight
`attribution.require_per_source()` refuse explicitement de démarrer dans ce cas : c'est
la garantie la plus importante du harnais, car une campagne qui mesure son propre refus
est pire qu'aucune campagne.

## À faire par la mission ou l'exploitant suivant

1. Provisionner et autoriser explicitement un VPS de test isolé, puis consigner sa
   configuration et le SHA déployé.
2. Exécuter la procédure de [../qa/load-procedure.md](../qa/load-procedure.md) et
   joindre la sortie JSON, complétée des relevés CPU/RAM/connexions par minute.
3. S'attendre à corriger des détails du harnais à la première campagne : il a été écrit
   contre les contrats et le code, jamais contre une API en marche.
4. Implémenter le scénario fichiers (image 1 MiB / PDF 5 MiB / vidéo 20 MiB, p95
   validation ≤30 s) lorsqu'un MinIO réel est disponible.
5. Ne pas considérer D01 ni la livraison MVP comme débloqués : la preuve de charge
   exigée par les conditions de sortie du plan n'existe toujours pas.

# X01 — assemblage de l'API

## Périmètre livré

- `app/wiring.py` : point unique de composition. Chaque module expose `create_router` et
  reçoit ses collaborateurs explicitement ; aucun module n'atteint un global.
- `app/main.py` : fabrique d'application, santé et amorçage des buckets.
- `tests/api/` : 26 tests d'assemblage.

## Décisions

1. **Une seule instance de `ProfileAccess`** est partagée par les profils, le contact et la
   recherche, pour que le quota de lectures publiques de `http.md` reste **un** groupe de
   120/min/IP et non un compteur par module.
2. **Deux clients de stockage distincts.** La sonde de disponibilité a besoin d'un délai de
   lecture court pour ne pas faire traîner un `/health/ready` ; le portfolio diffuse des
   fichiers et a besoin d'un délai long. Le module portfolio reçoit donc son propre client.
3. **Collaborateurs construits dans `create_app`, pas dans le `lifespan`.** Le routage a
   besoin d'eux avant que le serveur ne serve ; le `lifespan` ne fait plus que libérer le
   pool de connexions.
4. **uvicorn en mode fabrique** (`--factory app.main:create_app`). Auparavant
   `app = create_app()` s'exécutait à l'import, ce qui rendait la configuration obligatoire
   pour simplement importer `app.main` et cassait tout test important le module. La
   validation stricte au démarrage est conservée.

## Comment l'assemblage est prouvé

Une route non montée répond 404, et un chemin monté sous une autre méthode répond 405.
Donc « ni 404 ni 405, dans la forme d'enveloppe attendue » est exactement la preuve que la
route est câblée. Les 24 routes du contrat sont vérifiées ainsi, plus `/auth/me`,
`/auth/csrf` et `/auth/logout` qui sont imbriquées un niveau plus bas et que
l'introspection d'itinéraires ne montre pas.

La base de données refuse **toute** connexion dans cette suite. Le routage, les
intergiciels, l'enveloppe d'erreur et l'ordre des contrôles sont donc réels, les sondes sont
instantanées, et aucun PostgreSQL n'est nécessaire. Les routes privées répondent 401, 403 ou
503 ; les routes publiques n'exigent jamais de session.

## Contrôles exécutés

```
python -m ruff check .   # code 0
python -m mypy app       # code 0, 104 fichiers
python -m pytest -q      # 389 réussis, 2 ignorés, 241 bloqués faute de PostgreSQL
python -m pytest -q tests/api   # 26 réussis
```

## Limites

L'assemblage prouve que chaque route existe et refuse correctement un accès anonyme. Il ne
prouve **aucun** parcours fonctionnel complet : inscription → profil → recherche →
portfolio exige PostgreSQL et MinIO. Ce parcours reste à exécuter, et la commande de
démarrage n'a jamais été lancée contre une vraie base : `docker compose` n'est pas
disponible sur ce poste.
